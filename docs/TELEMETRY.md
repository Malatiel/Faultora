# Run telemetry

Set `FAULTORA_OTLP_ENDPOINT` on the CLI or runner process to send
OpenTelemetry traces and metrics to an operator-configured collector.
The value is the collector origin, for example `https://collector.example.com:4318`
or `http://127.0.0.1:4318` for a loopback collector. Use a standard TLS trust
store for HTTPS. The process uses OTLP/HTTP protobuf on `/v1/traces` and
`/v1/metrics`. Unset the variable to disable export.

The collector is part of the deployment environment. Keep its traffic within
the deployment's egress and retention policies. The setting comes from the
operator's environment and applies to the CLI, runner and MCP process. An
accepted execution produces one `faultora.run` span. Preview, preparation and
refused dispatches before execution do not start spans.

| Signal | Name | Meaning |
| --- | --- | --- |
| Trace | `faultora.run` | Time spent opening the runtime, executing the prepared run and cleaning up |
| Counter | `faultora.run.count` | Number of executions by outcome |
| Histogram | `faultora.run.duration` | Execution duration in seconds by outcome |

The only per-execution attribute is `faultora.outcome`. Its values are the
fixed run statuses `passed`, `failed`, `error`, `skipped` and `cancelled`.
The resource has the service name `faultora` and a random ID generated once
per process. Trace and span IDs are generated by the SDK. Payloads, targets,
run and node identifiers, file paths, credentials and errors from the run
remain in their normal local channels. This setting covers run-level spans
and metrics. Structured logs follow the existing local logging configuration.

Export uses a bounded span queue and background workers. Metrics are
aggregated and exported every ten seconds. An unavailable collector can drop
telemetry, while the run keeps its normal journal, result and exit code.
Requests use a 500 ms budget and process shutdown allows up to 1.2 seconds
for a flush. The transport accepts only a clean HTTPS or literal loopback HTTP
origin, follows no redirects and sends no authentication headers. The SDK
receives the HTTP status code of each export response.
